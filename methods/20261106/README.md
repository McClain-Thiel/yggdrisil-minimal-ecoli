Both validation studies pin native vEcoli to `b2078bd8e226c5d319bb9ddaa10a1f2f1fcfdbbc`, use one daughter per division, aerobic M9 glucose, seeds 101/211/307, and a 10,800-second simulated cell cap. The [strict v2 solver patch](baseline-validation/solver-recovery-v2.patch) has SHA256 `3a4a50fdc7b4d16277b7ce8d3cb76e2e2fd69132937a4d57cbb232b01a06592a`. Its unchanged-LP, optimal-status, finite KKT checks and explicit fallback logs apply to both studies. Biological parameters and failed attempts were preserved.

For agent validation, use the frozen agent-search application/framework and replace the files under `validation-application` with the exact validation overlay. The final controller was reconstructed solely by applying the two preserved text transformations to its original source; its resulting SHA256 matches the original validation-readiness record. No simulation or controller was run during reconstruction.

The original preparation and deployed manifests are both retained for the baseline validation. They differ because of documented operational backup repairs. Generated bytecode and packaging metadata are excluded from source snapshots and explicitly identified in the manifest where present in original records. Source code is stored in Git, not uploaded as scientific data to S3.

Input locations, frozen graph member hashes, final genotype identities, environment versions, model budgets, stop reasons, W&B artifact versions, detailed final analyses, and independent audits are in the linked ledger entries. Reproduction requires restoring those exact private S3 inputs and reviewing the original environment records; simply running the latest application checkout is not a reproduction of these historical runs.
